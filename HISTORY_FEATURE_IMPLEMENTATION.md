# History Feature Implementation Guide

## Overview
The History feature allows users to view all their previous design analyses with scores, dates, and timestamps. Every analysis is automatically stored in the database when completed.

## Components & Features

### 1. **History Page** (`/components/Pages/HistoryPage.jsx`)
The main history page accessible via `/history` route.

**Features:**
- 📊 Displays all user analyses in a sortable, filterable list
- 📅 Shows analysis date and time
- ⭐ Displays ARAI score and grade (A, B, C, etc.)
- 👁️ "View" button to navigate to detailed analysis report
- 🗑️ "Delete" button to remove analyses
- ⌛ Loading states and empty state handling
- 📱 Fully responsive design
- 🎨 Consistent styling with the dashboard

**Props:** None (uses `analysisService` to fetch data)

**State:**
- `analyses`: List of all analyses
- `loading`: Loading state
- `error`: Error message if fetch fails
- `deleting`: ID of analysis being deleted

### 2. **History Section** (`/components/Dashboard/HistorySection.jsx`)
Compact history widget shown in the dashboard.

**Features:**
- 🎯 Shows 5 most recent analyses
- 🔄 Auto-refreshes when new analysis completes
- 📊 Score and grade badges
- ⏱️ Smart date formatting (Today, Yesterday, etc.)
- 🔗 "View All History" button links to full history page

**Props:**
- `refreshTrigger`: Number that changes when to refresh the list

**State:**
- `analyses`: List of recent analyses
- `loading`: Loading state

### 3. **Dashboard Integration** (`/components/Dashboard/Dashboard.jsx`)
- Passes `refreshTrigger` prop to `HistorySection` after each analysis
- Automatically refreshes history when analysis completes
- Maintains analysis history across different tabs

## Data Flow

### When User Uploads a Design:
```
1. User uploads file → UploadAnalysisMultiple/UploadAnalysis
2. File sent to → /api/v1/analysis/upload (Backend)
3. Backend analyzes file (1-3 minutes)
4. Results saved to → Supabase database (analyses table)
5. Response returned with analysis_id, scores, timestamp
6. Frontend calls → handleAnalysisComplete()
7. setRefreshHistory() triggers → HistorySection refresh
8. User sees new analysis in history automatically
```

### When User Views History:
```
1. User navigates to /history page
2. HistoryPage component mounts
3. fetchHistory() calls → /api/v1/analysis/history
4. Backend queries → Supabase (sorted by created_at DESC)
5. Results displayed with full details
```

### When User Views Figma Analysis:
```
1. User inputs Figma URL → FigmaAnalyzer
2. URL sent to → /api/v1/analysis/figma-screens
3. Backend extracts frames and analyzes each
4. Results saved to → Supabase database (figma_analyses table)
5. Analysis appears in history automatically
```

## Database Schema

### `analyses` table (Image Uploads)
```sql
- id: UUID (primary)
- user_id: UUID (foreign key)
- design_name: string
- filename: string
- file_path: string
- status: string ('completed', 'processing', 'failed')
- arai_score: float (0-100)
- overall_grade: string ('A', 'B', 'C', 'D', 'F')
- conformance_level: string (WCAG AA, AAA, etc.)
- accessibility_score: float
- readability_score: float
- attention_score: float
- results: JSONB (full analysis details)
- created_at: timestamp (when analysis was created)
- updated_at: timestamp (last update)
```

### `figma_analyses` table (Figma Projects)
```sql
- id: UUID (primary)
- user_id: UUID (foreign key)
- file_key: string (Figma file key)
- file_name: string
- figma_url: string
- status: string ('completed', 'processing', 'failed')
- accessibility_score: float
- readability_score: float
- attention_score: float
- overall_score: float
- analysis_data: JSONB (full results with all frames)
- created_at: timestamp
- updated_at: timestamp
```

## API Endpoints

### Get Analysis History
```
GET /api/v1/analysis/history?limit=50
Authorization: Bearer <token>

Response:
{
  "analyses": [
    {
      "analysis_id": "uuid",
      "design_name": "Homepage Design",
      "filename": "homepage.png",
      "timestamp": "2026-04-16T14:30:45.123Z",
      "arai_score": 85.5,
      "overall_grade": "B",
      "conformance_level": "WCAG AA",
      "status": "completed"
    },
    ...
  ],
  "total": 15
}
```

### Delete Analysis
```
DELETE /api/v1/analysis/results/{analysis_id}
Authorization: Bearer <token>

Response:
{
  "message": "Analysis deleted successfully",
  "analysis_id": "uuid"
}
```

## Usage Examples

**Viewing History:**

2. See all previous analyses with dates and scores
3. Click "View" to see detailed report
4. Click "Delete" to remove an analysis

**From Dashboard:**
1. Click "History" tab
2. See 5 most recent analyses
3. Click "View All History" for complete list

### For Developers:

**Getting history in code:**
```javascript
const { analyses, error } = await analysisService.getHistory(1, 50);
analyses.forEach(a => {
  console.log(`${a.design_name}: ${a.arai_score}/100 - ${a.timestamp}`);
});
```

**Handling analysis completion:**
```javascript
const handleAnalysisComplete = (analysisData) => {
  // setRefreshHistory() automatically called
  // HistorySection will re-fetch latest analyses
  navigate('/history'); // Optional: redirect to history
};
```

## Troubleshooting

### Issue: History not loading
**Solution:**
1. Check network tab in DevTools
2. Verify authentication token is valid
3. Check Supabase connection in backend
4. Ensure user_id is properly set in session

### Issue: New analysis not appearing in history
**Solution:**
1. Wait for analysis to complete (status = 'completed')
2. Check that analysis was saved to database
3. Try refreshing the page manually
4. Check browser console for errors

### Issue: Delete operation fails
**Solution:**
1. Verify you have permission to delete (own the analysis)
2. Check network connectivity
3. Ensure analysis_id is valid
4. Try refreshing page and trying again
